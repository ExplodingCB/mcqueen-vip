# mcq_vehicle

CAN interface between the Jetson and the safety gateway. `dbc/mcqueen.dbc` is the single source of truth for frame layouts; both sides derive from it.

| Path | What it is |
| --- | --- |
| `dbc/mcqueen.dbc` | Frame and signal definitions, cycle times, fault bit layout, mode values |
| `generated/mcqueen.{h,c}` | Pack and unpack functions for every frame, generated by cantools through `tools/gen_can_code.py`; do not edit |
| `tools/gen_can_code.py` | Regenerates the above; CI fails if it is stale |
| `test/test_dbc.py` | Layout sanity, mode values against `mcq_msgs`, firmware test vectors in sync |

The firmware keeps its own small hand-written codec for `JETSON_COMMAND` (it must stay free of generated code it cannot audit) and its test suite compiles `generated/mcqueen.c` to prove the two agree byte for byte. The `gateway_bridge` node (SocketCAN in, `VehicleState` and `GatewayStatus` out, `VehicleCommand` in, `JETSON_COMMAND` frames out with the heartbeat and CRC) uses the generated code and is the next piece of this package.

Changing a frame: edit the DBC, run `python src/mcq_vehicle/tools/gen_can_code.py` and `python firmware/gateway/tools/gen_can_vectors.py`, update `firmware/gateway/src/command.c` if `JETSON_COMMAND` changed, and commit all of it together.
